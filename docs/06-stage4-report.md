# 단계 4 결과 — 용의자 / 목표 판정 / 점수

## 구현 범위
- 브리핑 화면: 임무 설명, 용의자 식별 단서 2개(아이콘), 필수 목표, 규칙, 건물 평면도(문, 잠긴 문, 탈출 구역). 두 사람이 Enter로 준비하면 시작
- 용의자 식별: 붉은 모자 + 노란 완장. 한 단서만 가진 위장 인물을 둬서 두 단서를 함께 봐야만 구분됨. 단서는 밝혀진 NPC에서만 보임(어두운 방은 손전등 필요)
- 목표 판정 (`MissionState`, 순수 로직): 용의자 구속, 살아 있는 민간인 전원 구속, 일반 적 사살 또는 구속, 탈출 구역 귀환
- 실패 조건: 용의자 사살, 두 경찰관 모두 사망. 민간인 사망은 점수만 감점
- 점수와 등급 (`ScoreRules` + `data/score.json`): 임시값. 성공/실패와 A~F 등급을 별도로 표시
- 결과 화면: 성공/실패, 원인, 목표 달성 현황, 점수, 등급, 감점 내역, 양 플레이어 생존 여부
- 호스트가 모두 계산하고 `rpc_mission`으로 복제

## 검증 (이 PC)
- 단위 테스트 190개: 임무 단계, 목표 판정, 실패 우선순위, 점수/등급 경계, 용의자/위장 단서 구성, 사살 알림
- 통합 테스트 46개: 브리핑 중 행동 차단, 성공(정상/한 명만 탈출 구역/민간인 사망 후 성공), 용의자 사살 실패(점수 40/E), 둘 다 사망 실패, 민간인 사살 점수만 감점
- 두 프로세스 시험: 기본/브리핑/결과/단서 시나리오와 Radmin 주소 경유에서 호스트와 클라이언트의 임무 상태, 점수가 일치
- 창 모드 스크린샷: 브리핑, 결과(실패), 현장 단서 확인
